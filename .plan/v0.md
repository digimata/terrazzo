# terrazzo v0

> v0 proves that a local directory can function as a precise spatial workspace for images, videos, folders, PDFs, and Markdown notes. It is complete when it can replace the current Figma Swipe canvas for one week of daily use without losing, duplicating, or obscuring files.

## 1. Context

The product definition lives in [the PRD](../docs/prd.md). [ADR-001](../docs/.decisions/adr-001-canvas-engine.md) selects tldraw, React, and Tauri, with Rust owning disk state. [ADR-002](../docs/.decisions/adr-002-note-editor.md) selects CodeMirror over a canonical Markdown buffer and reserves a syntax-visible mode for future Vim support.

Nothing is implemented. The first risk is not feature completeness. It is whether tldraw and media-heavy custom shapes perform reliably inside Tauri's WKWebView. The second risk is whether a filesystem-canonical canvas can reconcile external changes without corrupting layout identity. v0 resolves both before adding search, generation, or broader document editing.

---

## 2. Outcome

The user selects one local directory as the workspace root. terrazzo renders that directory as the top-level infinite canvas. Its files and immediate subdirectories appear as movable objects. Opening a subdirectory enters another canvas backed by that descendant directory. Navigation, watching, asset access, and file commands cannot leave the root.

The user can:

1. Import files by dragging them from Finder.
2. Arrange images, video posters, PDFs, Markdown notes, and folders with precise canvas controls.
3. Play a selected video without activating every video on the canvas.
4. Open and edit a Markdown note inside terrazzo.
5. Navigate recursively through folders and return through breadcrumbs.
6. Quit and reopen the application without losing layout.
7. Rename, add, modify, or remove files in Finder and see terrazzo reconcile safely.
8. Move an item to the system Trash through an explicit command.

v0 is a single-user macOS application. It runs against local files and requires no account, server, synchronization service, or database.

## 3. Scope

### 3.1 — Included

#### Application shell

- Tauri v2 application with a React and TypeScript frontend.
- One main window and one active workspace.
- Native directory picker for opening or creating a workspace.
- `.canvas/workspace.json` at the root with schema version, durable workspace UUID, and display name.
- The selected root is the top breadcrumb. Descendant folders have no artificial depth limit; navigation never goes above the root.
- Workspace access restricted to the selected canonical root.
- Development build first. Resolve the tldraw production license before packaging a distributable build.

#### Canvas

- Smooth pan and zoom.
- Click, shift-click, and marquee selection.
- Multi-item drag and resize.
- Aspect-ratio lock.
- Grid display and configurable grid snapping.
- Alignment guides against sibling objects.
- Arrow-key nudge at 1 pixel and Shift-arrow nudge at 10 pixels.
- Numeric position and dimensions inspector.
- Bring forward, send backward, bring to front, and send to back.
- Undo and redo for presentation-state changes only.

#### Files and media

- Images: PNG, JPEG, WebP, GIF, and SVG.
- Videos: MP4 and MOV poster generation, explicit playback, pause, seek, and poster restoration.
- PDFs: first-page preview and open through the system viewer.
- Markdown: static styled preview on the canvas and in-app editing.
- Unsupported files: labeled generic cards that open through the system default application.
- Finder drag-in copies by default. Move requires an explicit modifier or command.
- Explicit Move to Trash removes the file and its layout record after the Trash operation succeeds.

#### Recursive navigation

- Immediate subdirectories render as folder cards.
- Double-click enters a folder canvas.
- Breadcrumbs return to any ancestor through the workspace root; no parent action exists at the root.
- Back and forward navigation restore the prior viewport and selection.
- Folder preview shows a bounded sample of child thumbnails without recursively mounting child canvases.

#### Persistence and reconciliation

- `.canvas/layout.json` per directory, keyed by durable UUIDv7.
- Root-only `.canvas/workspace.json` defines workspace identity and the filesystem boundary.
- Schema version on every sidecar.
- Identity hints use path, device, inode, modification time, and size.
- Nanosecond timestamps serialize as strings.
- Sidecars write through a sibling temporary file and atomic replacement.
- Layout writes are debounced and flushed on navigation or application close.
- Recursive filesystem watching runs in Rust.
- New files receive deterministic default placement.
- External modifications refresh previews.
- External renames preserve UUID and layout when identity reconciliation succeeds.
- Ambiguous or missing files render as tombstones.
- Intentional Trash removes the corresponding record and does not leave a tombstone.
- Thumbnail and poster caches are derived and rebuildable.

#### Markdown editor

- Clicking a Markdown card enters a full-window document mode inside terrazzo.
- One CodeMirror 6 instance mounts for the active document.
- Canvas shortcuts and pointer interaction are disabled during document mode.
- The `.md` text buffer remains canonical.
- v0 concealed writing supports paragraphs, H1–H3, bold, italic, links, blockquotes, bullet lists, numbered lists, task lists, inline code, and fenced code blocks.
- Formatting commands edit Markdown delimiters programmatically.
- An explicit source toggle reveals the complete Markdown buffer.
- Preview cards use cached sanitized HTML, never read-only CodeMirror instances.
- Autosave is debounced and uses the Rust atomic-save path.
- External modification reloads a clean document and produces a conflict state for a dirty document.
- Document undo history is independent from canvas undo history.

#### Performance and safety

- Viewport culling for off-screen canvas objects.
- At-rest and off-screen videos use poster images, not live video elements.
- No more than four live video elements.
- A restrictive content security policy.
- Raw HTML in Markdown is disabled in v0.
- Canonical path validation prevents commands and symlinks from escaping the workspace.
- The webview receives narrow named commands and never receives general shell access.

### 3.2 — Deferred

- Vim mode. ADR-002 preserves the required syntax-visible architecture.
- Image generation, image variations, text-to-video, and image-to-video.
- Search, indexing, tags, and saved filters.
- Web clips and remote bookmarks.
- Multiple workspaces open simultaneously.
- iCloud-specific reconciliation and cross-machine rename recovery.
- Collaboration, comments, sharing, and multiplayer.
- Mobile applications.
- Rich document formats such as DOCX, Pages, and editable PDF.
- Freehand drawing, vectors, connectors, components, and other design-tool features.
- Audio-specific cards and waveforms.
- Generation history and provenance UI.
- Packaging for Windows or Linux.

### 3.3 — Explicit non-goals

v0 does not prove that terrazzo can replace Finder, Figma, a Markdown editor, or a media editor independently. It proves that the combination is useful as a local spatial workspace.

v0 does not guarantee layout preservation after a rename performed on another machine while terrazzo is closed. It preserves content and shows an unambiguous tombstone rather than guessing.

## 4. Architecture

### 4.1 — Runtime boundary

```text
React + tldraw + CodeMirror
            │
     typed Tauri commands
            │
Rust workspace service
├── workspace root and path validation
├── directory scans and file metadata
├── UUID/path/inode reconciliation
├── recursive watcher
├── atomic sidecar and document writes
├── thumbnail and poster job queue
├── asset streaming
└── system open and Trash operations
```

TypeScript owns visible application state. Rust owns every interaction with disk. The frontend cannot construct arbitrary filesystem or shell commands.

### 4.2 — Sources of truth

| State | Source of truth | Rebuild behavior |
|---|---|---|
| File content | Ordinary files | Never derived |
| Workspace identity and boundary | Root `.canvas/workspace.json` plus user authorization | Re-select root if authorization is lost |
| Directory membership | Filesystem | Rescan directory |
| Item identity and layout | `.canvas/layout.json` | Content survives if lost; layout does not |
| Canvas runtime records | tldraw store | Rehydrate from directory and sidecar |
| Previews and posters | `.canvas/thumbnails/` | Regenerate |
| Active Markdown buffer | CodeMirror state, then `.md` after save | Recovery draft until atomic save succeeds |
| Navigation history | Application memory | May reset on restart in v0 |

The tldraw store is a projection, not persistence. Opening a directory combines its current filesystem listing with `layout.json` to construct shapes. Shape changes project back into the sidecar.

### 4.3 — Application state

```typescript
type AppMode =
  | { type: "canvas"; directoryId: string }
  | { type: "document"; itemId: string; view: "writing" | "source" }
  | { type: "media"; itemId: string }
```

Vim is absent from v0, but the document mode does not assume that Escape will always close the editor. Keyboard ownership remains inside the active mode so a future Vim compartment can claim Escape without changing canvas architecture.

### 4.4 — Sidecar writes

Sidecar changes accumulate in memory during direct manipulation. The frontend sends a typed layout delta after the interaction ends. Rust validates item IDs and coordinates, applies the delta to the current sidecar model, writes a sibling temporary file, and atomically replaces `layout.json`.

The watcher must distinguish self-generated writes from external changes. A completed Rust write returns the new sidecar revision; watcher events carrying that revision are suppressed.

### 4.5 — File deletion

Deletion is a filesystem operation:

1. Confirm the target UUID still resolves inside the active directory.
2. Send the file or directory to the system Trash.
3. Remove its layout entry only after Trash succeeds.
4. Emit one reconciled change to the frontend.
5. Exclude the operation from canvas undo and redo.

The UI names this action **Move to Trash**. It never labels a hard delete as remove or hide.

## 5. Implementation sequence

### 5.1 — Gate 0: renderer and shell spike

Build one disposable screen before the application structure hardens.

1. Render 200 mixed image and video-poster shapes in tldraw.
2. Pan and zoom at the target frame rate.
3. Play and seek four simultaneous MP4/MOV videos through the Tauri asset path.
4. Drop Finder files at exact world coordinates.
5. Select a workspace dynamically and stream assets only from that root.
6. Watch a recursive directory.
7. Preserve layout through an external rename.
8. Generate a poster with the ffmpeg sidecar.

Pass means no blocking renderer defect and sustained 60 fps during the defined canvas test on the development Mac. A renderer-specific failure switches the shell to Electron before product implementation. A Rust workspace service failure is fixed without changing shells.

### 5.2 — Milestone 1: workspace skeleton

1. Scaffold Tauri, React, TypeScript, and Rust.
2. Add the directory picker and active-workspace lifecycle.
3. Create or load root `.canvas/workspace.json`.
4. Define typed command payloads and error variants.
5. Implement canonical root validation and descendant directory scanning.
6. Hydrate a tldraw canvas from one directory.
7. Add placeholder shapes for files and folders.

Deliverable: open a directory and see one canvas object per immediate child.

### 5.3 — Milestone 2: layout and navigation

1. Define sidecar structs and schema version 1.
2. Map tldraw shape changes to layout deltas.
3. Implement atomic sidecar persistence.
4. Add precision controls and layout-only history.
5. Implement folder entry, breadcrumbs, back, and forward.
6. Restore each directory's viewport and selection during the session.

Deliverable: arrange nested folders, restart terrazzo, and recover the same layout.

### 5.4 — Milestone 3: media and file operations

1. Add image, video, PDF, Markdown, generic-file, and folder shapes.
2. Add viewport culling and poster-at-rest behavior.
3. Implement the thumbnail and poster queue.
4. Add Finder copy-in and explicit move.
5. Add system open and Move to Trash.
6. Add watcher reconciliation and tombstones.

Deliverable: use a real swipe-file directory without changing its organization outside deliberate commands.

### 5.5 — Milestone 4: Markdown editing

1. Add full-window document mode.
2. Add CodeMirror with the supported Markdown dialect.
3. Implement concealed decorations and formatting commands.
4. Add explicit source mode.
5. Add static sanitized card previews.
6. Add autosave, revision checks, atomic writes, and conflict state.
7. Separate document history from canvas history.

Deliverable: create or open a Markdown note, edit it comfortably, return to the canvas, and verify the ordinary `.md` file contains the expected text.

### 5.6 — Milestone 5: hardening

1. Run the complete flow matrix in §7.
2. Profile the 200-item canvas and eliminate frame-time regressions.
3. Test malformed sidecars, missing files, permission loss, and process failures.
4. Test crash recovery during layout and document saves.
5. Use terrazzo as the primary Swipe canvas for one week.
6. Record friction, failures, and scope changes before declaring v0 complete.

## 7. Verification

### 7.1 — Automated

- TypeScript type checking passes with zero errors.
- Frontend linting passes with zero warnings.
- Rust formatting, tests, Clippy pedantic, and documentation tests pass with zero warnings.
- Sidecar round-trip fixtures preserve every supported field.
- Reconciliation tests cover same-path replacement, live rename, inode reuse, ambiguity, deletion, and atomic-save inode changes.
- Path tests reject traversal and symlink escape.
- Workspace tests reject navigation, watching, asset access, and mutations outside the selected root.
- Markdown fixtures cover every concealed construct and verify that formatting commands produce valid source.
- Save-conflict tests prove an external edit is never overwritten silently.
- Malformed sidecars recover without modifying files.

### 7.2 — Manual flows

1. **Open and restore**
   - Open a directory containing at least 200 mixed items.
   - Arrange 20 items across a large canvas.
   - Enter two nested folders and arrange their contents.
   - Restart and confirm every layout returns.

2. **Precision**
   - Snap items to the configured grid.
   - Align multiple edges and centers using guides.
   - Edit coordinates numerically.
   - Nudge at 1 and 10 pixels.
   - Undo and redo the complete layout sequence.

3. **Media**
   - Render each supported image type.
   - Play, seek, pause, and restore posters for four videos.
   - Confirm off-screen videos do not remain live.
   - Open a PDF and unsupported document through the system application.

4. **Filesystem**
   - Copy files in through Finder drag-and-drop.
   - Rename and modify files externally.
   - Confirm identity and layout survive a detected rename.
   - Delete a file externally and confirm a tombstone.
   - Move a file to Trash inside terrazzo and confirm no tombstone remains.
   - Attempt a name collision and confirm no overwrite occurs.

5. **Markdown**
   - Open a note from its canvas card.
   - Apply every supported formatting command.
   - Toggle source and confirm the expected Markdown.
   - Autosave and reopen the file.
   - Modify the file externally while clean and while dirty.
   - Confirm the clean document reloads and the dirty document enters conflict state.

6. **Failure handling**
   - Deny access to a file.
   - Break and then restore the ffmpeg sidecar.
   - Corrupt `layout.json`.
   - Disconnect or move the workspace root.
   - Attempt to navigate above the root and follow a symlink outside it.
   - Confirm each failure is labeled and no content is deleted or overwritten.

### 7.3 — Performance

Use one fixed fixture and record the development machine specification:

- 200 objects: 120 images, 60 video posters, 10 Markdown cards, and 10 folder cards.
- 2560 × 1440 viewport.
- Warm thumbnail cache.
- Continuous scripted diagonal pan and zoom between 25% and 200%.
- Four 1080p videos playing during the playback test.
- Target: p95 frame time at or below 16.7 ms during canvas manipulation.
- Target: no live media element for a culled or at-rest video.

## 8. Exit criteria

v0 is complete when all conditions hold:

1. Gate 0 selects Tauri or Electron with recorded evidence.
2. Every included capability in §3.1 passes its manual flow.
3. Automated checks pass with zero warnings.
4. The performance fixture meets its target on the development Mac.
5. No known path can overwrite or permanently delete a file without an explicit filesystem command.
6. The Swipe directory has been used through terrazzo for seven consecutive days.
7. No content-loss, layout-corruption, or silent-conflict defect remains open.
8. The v0 review records what was used, what was ignored, and whether to proceed to generation, search, or editor refinement.

Vim and generative media remain deferred. Their data and input boundaries are preserved, so adding them does not require replacing the editor, storage model, or canvas architecture.
