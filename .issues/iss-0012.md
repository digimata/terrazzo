# ISS-0012 — Restore canvas selection after closing focused media

GitHub: [#12 — Restore canvas selection after closing focused media](https://github.com/digimata/terrazzo/issues/12)

## Summary

Opening focused media unmounts the canvas. Terrazzo stores and restores the directory camera, but it does not preserve the selected durable item IDs, so closing media does not return to the exact prior canvas state required by PR-031.

## Evidence

- `src/app/App.tsx:57-67` replaces the canvas with `MediaView`.
- `src/canvas/CanvasView.tsx:45-46` caches only camera state.
- `src/canvas/CanvasView.tsx:425-430` saves only the camera during unmount.
- Selection is reconstructed as empty when the canvas remounts.

## Proposed change

Choose one explicit lifecycle:

1. Keep the canvas mounted and inert beneath the focused media overlay, or
2. Persist camera plus selected durable item IDs before unmount and restore them after hydration.

Whichever design is selected must also define what happens when a previously selected item is renamed, removed, or becomes a tombstone while media is open.

## Acceptance criteria

- Open media from a selected item, close it, and return to the same directory, camera, zoom, and selection.
- Multi-selection is restored when the opened item was part of a larger selection.
- Missing IDs are ignored safely while surviving IDs remain selected.
- Backdrop close and Escape have identical restoration behavior.
- In-flight layout persistence is not lost during the transition.
- An automated interaction test covers the full open and close sequence.
