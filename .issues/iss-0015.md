# ISS-0015 — Add saved workspaces, a default workspace, and a bottom-left root switcher

GitHub: [#15 — Add saved workspaces, a default workspace, and a bottom-left root switcher](https://github.com/digimata/terrazzo/issues/15)

## Summary

Terrazzo should persist a list of registered workspace roots and one default workspace at the application level. Normal launch should open the usable default directly, and a compact switcher in the bottom-left canvas chrome should let the user change between saved roots.

This implements the saved-workspace and switcher slice described provisionally in docs/.ideas/idea-0001.md. CLI behavior remains separate.

## Proposed behavior

1. Store registered workspaces outside every workspace, using durable workspace identity plus the current canonical root path.
2. Store one optional default workspace.
3. On normal application launch:
   - open the default workspace directly when it is available;
   - otherwise open the workspace manager;
   - do not show an intermediate start screen when a usable default exists.
4. Add a bottom-left workspace switcher that:
   - lists saved workspace roots by display name;
   - clearly marks the active workspace;
   - switches the current window to the selected root;
   - provides an action to register or initialize another workspace.
5. Treat missing or inaccessible saved roots as unavailable entries that can be relocated or removed rather than silently deleting them.
6. Let the user explicitly set or change the default workspace.

## Lifecycle and safety

Switching workspaces changes the application filesystem authority boundary. Before activating the new root, Terrazzo must stop the old root watcher, revoke or replace its asset-protocol scope, clear root-specific transient state, and then establish authority for the new root.

Per-directory canvas state may remain associated with its workspace, but cameras, selections, open media, pending layout writes, and filesystem events must never leak between roots.

## Acceptance criteria

- Registered workspaces and the default selection survive application restarts.
- Launching Terrazzo with a usable default opens its root canvas directly.
- With no usable default, Terrazzo opens the workspace manager and explains unavailable saved roots.
- The bottom-left switcher lists saved roots, identifies the active one, and switches to another root without opening a second state owner.
- The user can register a root, remove a saved root without deleting its files, and explicitly choose the default.
- Selecting an unavailable root produces a recoverable relocate/remove flow.
- Workspace switching flushes or reports pending layout writes before revoking the old root.
- Watchers, asset access, filesystem commands, and events are scoped exclusively to the newly active root after a switch.
- Tests cover persistence, default launch, switching, unavailable roots, pending writes, and authority teardown.

## Out of scope

- The terrazzo CLI and terrazzo init.
- Simultaneously active multi-workspace windows.
- Deleting a workspace or its contents from disk.
