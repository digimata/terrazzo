# ISS-0016 — Layout changes revert after opening and closing a note

GitHub: [#16 — Layout changes revert after opening and closing a note](https://github.com/digimata/terrazzo/issues/16)

## Summary

Recent canvas layout changes can be lost when the user opens a Markdown note and then returns to the canvas. Cards reappear at their previously persisted positions instead of the positions visible immediately before opening the note.

## Reproduction

1. Open a workspace canvas.
2. Move or resize one or more cards.
3. Click a Markdown note to enter the document view.
4. Close the document view and return to the canvas.
5. Observe that the recent layout changes have reverted.

## Expected behavior

Opening and closing a note must preserve the exact canvas layout that was visible when the note opened, including position, size, rotation, and stacking order.

## Evidence and likely failure mode

- App.tsx replaces CanvasView with DocumentView when a note opens, unmounting the canvas.
- CanvasView debounces layout persistence by 400 ms.
- The cleanup path starts applyLayout without awaiting it, clears the dirty IDs first, and suppresses any error.
- Returning from the note immediately mounts a new canvas and hydrates it with openDirectory.
- There is no barrier guaranteeing that the final layout write completes before the new hydration reads layout.json.

This creates a write/read race and also makes a failed teardown write unrecoverable. It is related to #11 but has a specific user-visible transition and reproduction path.

## Proposed change

Introduce an explicit canvas-to-document transition that flushes dirty layout deltas and confirms persistence before the old canvas state is discarded or a replacement canvas hydrates. Prefer keeping the canvas mounted beneath the document view if that provides a cleaner lifecycle. Preserve dirty state and surface a recoverable error if persistence fails.

## Acceptance criteria

- Moving a card and immediately opening a note does not revert the move after returning.
- Resizes, rotations, and stacking changes survive the same transition.
- Returning immediately from the note cannot hydrate layout state older than the final canvas flush.
- A failed final write retains the dirty deltas and displays a recoverable error instead of silently clearing them.
- Repeated note open and close cycles do not introduce stale writes that overwrite newer layout state.
- Automated tests cover opening a note both inside and outside the 400 ms debounce window, an immediate return, and a simulated persistence failure.
